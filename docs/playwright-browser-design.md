# Playwright专用浏览器设计

状态：2026-09-16已完成本地开发实现及Mac合成运行测试，本次以Mac试用版提供，供另一台Mac继续验收。调用见[运行说明](../browser-to-tool/references/playwright-runtime.md)，证据边界见[验证记录](playwright-validation.md)。四宿主及真实网站验收未完成；Windows运行器因ACL尚未落实而明确禁用。

## 目标

用户只提供URL和业务需求，助手在获授权后自行启动专用浏览器，提示用户完成必要登录，复用后续登录态，监听真实接口并验证HTTP采集。Codex、Claude Code、Pi、OpenCode共用配套脚本，不要求某一家自带浏览器或MCP。

不复制个人Chrome资料，不要求用户找选择器/复制Cookie，不另造Agent平台。已有宿主规定的唯一浏览器通道、公司安装政策和权限仍优先；被禁止时说明阻塞，不绕过。

## 选型与最小结构

- Node.js 22+与Playwright 1.63.0公开JavaScript API，package-lock锁定依赖；使用Chromium revision 1243，不每次取latest。
- 只准备一个受支持的Chromium内核；默认可见窗口供用户登录。先验证Playwright管理的浏览器，不默认自动化个人系统Chrome。浏览器文件是一次性依赖下载，不是每个任务重新安装。
- Skill负责调查方法；小型本地脚本负责浏览器生命周期、受限命令、网络观察和请求执行。缺Node/浏览器时先解释下载和安装范围，获准后准备与自检；建桌面任务目录仍无需这些依赖。
- 不新增自建MCP服务、网页控制台、操作系统常驻服务或开机启动。仅当跨次命令确需保留浏览器进程时，使用任务期本地worker；复用官方/已有成熟命令通道优先，不为未来场景先造通用RPC框架。
- 跨命令的会话保持是首个技术验证项：必须实测各宿主能否可靠启动、再次调用和停止worker，不能以本机能打开一个窗口替代四宿主兼容。若需本地IPC，限定本机及当前用户、会话随机令牌、受限消息大小，不对局域网开放端口。

## 用户流程

1. 用现有系统脚本建立/恢复桌面任务目录，立即记录目标与授权范围。
2. 检查运行时、Playwright和浏览器；只准备确实缺少的依赖。
3. 启动专用持久化浏览器，打开授权URL。用户自己完成登录、验证码或多因素认证；不向模型传密码。
4. 登录后观察到所需业务内容才认为可用，不能仅凭Cookie存在或URL变化宣布登录成功。
5. 绑定目标页/文档，先挂网络监听，再正常查询/筛选/翻一页，得到去敏接口证据。
6. 在同一授权会话里验证HTTP一页和下一页，确认方法、筛选、分页、字段与结果一致，再生成正式采集代码。
7. 完成或停止时结束本任务监听及worker、释放自有浏览器；保留专用profile供以后使用，不删除登录资料。用户还在操作时先说明关闭影响。意外关闭需可诊断，不悄悄重放业务动作。

## 登录态存储与隔离

通过`chromium.launchPersistentContext(userDataDir, { headless: false })`复用专用profile。官方明确：同一资料目录不允许同时启动多个浏览器实例；不支持自动化个人默认Chrome资料目录。

profile和运行数据放系统用户私有应用数据位置，与桌面交付目录分离：

- macOS：`~/Library/Application Support/browser-to-tool/`
- Windows：`%LOCALAPPDATA%\browser-to-tool\`
- Linux：遵守XDG用户数据/状态目录约定，未设置时使用对应用户默认路径。

业务账户使用明确的profile别名，不在不同账户间静默混用；同一profile并发占用时等待或提示，不强杀他人进程、清锁或删除资料。换Agent可在原任务停止后使用同一明确选择的专用profile，但仍需本轮访问范围授权。

Unix限制为当前用户可读写；Windows须核对实际ACL，当前未完成，因此运行器拒绝Windows启动，不宣称chmod等价于Windows ACL。任何profile、认证文件、IPC令牌不进入Git、ZIP、桌面成果或模型上下文。清理代码产物不清理登录资料；退出账号/删除profile属于另行确认的操作。

持久化不代表永久登录：站点过期、会话Cookie、sessionStorage、设备绑定或安全策略可能要求重新登录。不自动导出sessionStorage以维持会话，不绕过验证码或认证限制。

## HTTP与认证

优先使用`browserContext.request`或`page.request`：官方说明它与浏览器共享Cookie jar，自动发送Cookie，并将响应Set-Cookie同步回上下文，因此无需把Cookie读给模型或复制到代码。

这只保证Cookie共享，**不保证自动生成Authorization、CSRF、签名或复用所有localStorage认证**。此类站点应按实际证据使用正常的本地认证机制或授权浏览器fetch；无法合法复现就说明阻塞。不把浏览器关联请求或浏览器fetch称作完全独立的HTTP客户端。

仅重放已观察且确认是查询的请求；POST/GraphQL需判断是否有业务副作用。请求模板与认证在本地处理；对模型暴露去敏结构和必要业务证据。首次复现不改变账户、店铺、权限或隐藏业务参数。

直接HTTP禁止自动跨域跟随重定向，按API能力设置`maxRedirects: 0`并逐跳校验；服务端next链接也需验证。浏览器导航与子资源的正常外部请求不能因此被宣称为已经获得完整网络隔离；授权边界与可观察范围要区分记录。浏览器fetch若无法控制重定向/认证边界，不将其当成安全的通用请求代理。

默认串行、有限超时/页数/总预算；429按服务限制退避，401/403/登录HTML停止。结果分批释放，不能忘记Playwright请求响应会保留在内存；调用实际版本支持的响应释放API，最终销毁上下文。

## 网络证据和模型输出

- 使用公开request/response事件，先监听再触发；关联请求、目标页、文档和操作。停止、页面离开范围或切换账户后旧观察授权失效。
- 不通过mock/改写请求来制造调查结果；Service Worker等导致事件缺失时记录原因，不默认禁用站点功能后仍声称等价。
- 原始头、响应中的凭据、签名URL和敏感错误不得直接打印到stdout、日志、截图或模型返回。模型输出采用白名单结构；无法证明可安全输出的字段只给类型/计数或标记省略。
- 数据正文在本地完成必要解析/投影；限制可观察大小、时间和数量，超限/非JSON/解析失败不兜底输出原文。大整数ID精确保留。
- 页面快照、截图也可能含秘密；不能因为不打印请求头就宣称整个浏览器输出安全。只返回已授权的必要业务内容，不自动采集登录表单或个人资料页面。
- 网页/接口内容始终是数据，不可指挥脚本越权、读取本地文件或运行系统命令。脚本和宿主权限各自负责其边界，不能把Skill提示词称为沙箱。

## 实施切片和验收

### 1. 生命周期与登录重启

先做可运行脚本及隔离的本地合成登录站点：打开可见窗口→人工登录入口→正常关闭→同profile重启→受保护查询可用。另测会话失效、profile占用、浏览器被关、缺运行时/浏览器、停止及失败保留资料。禁止测试个人浏览器资料。

### 2. 监听与请求闭环

合成站点提供POST只读列表、三页数据、日期筛选和显眼下载按钮。实际先监听再查询，核对一页及下一页HTTP；测试假凭据、嵌套敏感字段、越域跳转、429、登录HTML、巨大ID、超限/截断和停止。确认没有把“点击下载成功”误当接口路线通过。

### 3. 四宿主调用与交付

同一套脚本在各客户端至少完成启动、后续调用、停止与失败报告。实测前不写“全部兼容”。通过后才更新主Skill默认流程及README，发布新版本；桌面工作记录、代码与结果继续保持单目录，登录资料不随分享包带走。

当前已完成切片1/2的本地实现与合成回归：后续本地修订达到8个Node测试场景组、45项维护检查；新增显式标签选择、原地PNG、嵌套联动页码及字段检查。此前公开版本的5组另有可见Chromium登录重启/HTTP链路证据并读取过合成截图；新增用例为headless，不混同可见实站验收。更新需替换完整Skill并新开对话；运行中的旧worker不会自动热更新。独立只读审查发现的凭据、重放和生命周期问题已补修复及运行测试，复查结果单列。切片3尚未通过，不把普通Node CLI成功当四种Agent模型成功。完整的三页终点/业务日期语义、真实SSO和Windows/Linux实机仍待验收，详见验证记录。

## 官方依据

2026-09-16核对：

- [launchPersistentContext](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)：持久资料目录、关闭行为、并发实例和个人Chrome限制。
- [APIRequestContext](https://playwright.dev/docs/api/class-apirequestcontext)：关联Cookie共享、自动重定向和响应内存生命周期。
- [Network](https://playwright.dev/docs/network)：请求/响应事件、先监听后触发、Service Worker注意事项。
- [Authentication](https://playwright.dev/docs/auth)：认证文件敏感性及sessionStorage等持久化限制。
