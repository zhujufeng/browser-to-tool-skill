## 对应修正

| 证据 | 根因与修正位置 |
|---|---|
| 只提供Python文件与终端命令，用户不知道怎么启动 | 主流程将“入口→核对结果→找到文件”作为完成条件；验证清单指定按OS生成最小启动入口，测试无关工作目录及实际运行时 |
| 浏览器可打开页面，脚本首次运行却报证书错误 | 环境参考要求从成品入口做小样本联网；区分解释器CA、企业代理与宿主限制，修复后重跑，不以语法检查宣称已修复 |
| 成功提示只有相对输出路径，用户不知道文件在哪 | 成品显示完整/部分、数量、绝对路径与打开方式；聊天同时给真实文件链接，重复运行不能覆盖旧结果 |
| 展示的详情模式仍设`extract_flat='in_playlist'`，导出列包含详情指标 | 按库官方语义核验实际模式与必需字段；导出行数或列头不能证明详情完整 |
| 无浏览器后复用现成站点库 | 保留这种简单实现路线，补充库版本/字段/跨页核验，不要求为复用可信库重新逆向，也不把导入成功说成实站成功 |

证书问题的具体原因不能由一条报错推定。[Python官方macOS说明](https://docs.python.org/3/using/mac.html)只适用于对应发行版的安装流程，企业CA需按组织规则处理。[yt-dlp官方参数说明](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py)明确`in_playlist`不展开列表内视频；本次未访问目标站点验证详情可用性。
