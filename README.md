# Browser to Tool · 看网页，做工具

**让编码助手为你开发采集脚本或浏览器插件，做好后直接使用，日常采集不用再打开 Codex。**

例如：每天整理商品销量、按日期导出订单、把后台列表整理成表格。你提供网址、数据范围和想要的结果；助手检查环境、调查网站、编写并验证工具。你不需要写代码、找接口或打开浏览器控制台，需要时亲自登录、授权，并核对业务口径。

开发和维护阶段：这是供编码助手加载的 Skill，需要能操作本地文件、执行命令的助手；只有普通聊天窗口还不够。支持适配 Codex、Claude Code、Pi、OpenCode，但安装成功不代表每个网站都能处理。

日常使用阶段：同事点击插件按钮，或打开脚本的启动文件，设置日期后采集并导出。成品不依赖编码助手或模型逐次决策；可能仍需要浏览器、网站登录，以及首次准备的本地运行环境。

**当前建议小范围试用。** 配套浏览器脚本是 Mac 试用版；Windows 的配套运行器明确禁用，可否使用其他通道取决于已有工具。四种客户端的完整流程及真实后台仍待验收。团队先选一种已有客户端和统一电脑环境，由维护者协助首次准备；没有编码助手的同事先由维护者或 IT 协助准备公司允许的客户端，不需要自行挑选技术组件。

同事可以请助手为自己开发工具，也可以复用已经做好的脚本或插件；仅使用成品的人不必安装这个 Skill 或编码助手。每个人使用自己的授权登录。开发期配套运行器的系统限制不等于成品插件或脚本的系统限制，成品需在目标电脑上单独验收。

## 最简单的安装方式

把这段话发给你正在使用的编码助手：

> 请从 https://github.com/zhujufeng/browser-to-tool-skill 安装 browser-to-tool Skill。先读取 README 和 Skill 内容，只将完整的 browser-to-tool 文件夹安装到当前客户端的个人技能目录；已有同名版本先询问并备份。不要重装客户端、修改其他配置或自动安装浏览器依赖。没有 Git 时可以下载 ZIP。完成后告诉我如何调用。

更新已有版本时，沿用实际安装位置并备份，记录来源提交号及安装后内容校验结果；拿不到提交号就记录主文件摘要值。更新后新开对话，核对助手实际读取的路径和内容，不能仅凭“14个文件已替换”或“下一轮生效”认定加载成功。不要在多个技能目录重复安装来碰运气。

**不需要为了安装 Skill 先装 Node、Python 或 Git。** 当前客户端需要有下载/文件操作能力；工具依赖按具体任务检测，确实需要安装时先说明并征求同意。

## 怎么用

```text
请使用 browser-to-tool，把这个后台昨天的商品数据整理成表格：<后台网址>。
需要商品名称、销量和销售额，只处理当前店铺。
先给我几行核对，确认后再处理全部。我以后每天都要用。
需要我登录时告诉我。请交付不用打开编码助手就能运行的脚本或插件，告诉我从哪里启动。
```

只需说明网址、范围、结果和使用频率，不用在需求里写“HTTP”或“分页”。助手会自行调查接口并验证。继续修改时说：

> 继续桌面的“日期_商品采集工具”任务，增加日期筛选，不另建文件夹。

**第二天使用**：无需启动编码助手。按交付说明打开插件或脚本启动文件，选择日期，开始采集并导出；之前的结果保留。日期输入、采集、停止、完成或失败提示都由成品提供。

**拿到工具时应当看到**：可直接打开的启动入口（Mac脚本如`开始采集.command`，或浏览器插件按钮）、明确的运行状态、完成后的文件位置及打开方式。只有源码或终端命令、尚未跑通目标网站时，应标记为“待验证版本”；“导出了多少行”也不能替代字段和范围核对。

涉及“视频列表＋逐个进入详情”等需求时，成品应自动取得列表、保存去重清单、逐项取得详情，再按同一视频关联导出；不用同事逐个复制链接，也不能只交一列详情网址。可以列表用接口、详情用获准的页面操作，两段都由成品执行。助手先用少量不同对象生成并核对真正的样本表格，再扩大范围；字幕正文、评论内容等分别验证。某些字段暂时失败时，已取得的数据可以先形成明确标记的部分预览，并说明哪些待补；部分表格、完整数据和可独立使用的工具分别验收。需求和权限已经明确后，助手应继续执行，不在“页面能打开了，接下来会做”处停下等你催。

标题、简介默认保留你所指网站页面的内容与语言，不擅自翻译。页面中文而采集结果英文时，应核对同一视频的来源、语言及导出，不能拿英文详情覆盖已核对的中文标题，也不能翻译回中文冒充采集成功；原本英文和中英混合标题照原样保留。

**登录过期**：按照成品提示在指定浏览器重新登录，再从同一入口运行；不需要复制 Cookie 或请 Codex 每次接管。没有已验证的断点续传时，工具应说明需要重新运行，不能假装从断点继续。

**需要改功能或网站接口变了**：这时再把原任务目录交给编码助手，请它检查、修改和重新验证。开发阶段由助手采到一次数据，不等于已经交付了可独立运行的工具。

每个新需求默认保存在电脑的真实桌面，不是Codex等客户端的聊天会话目录：

```text
桌面/日期_任务名/
├── 工作记录.md    调查依据、分析、进度和验证结果
├── 使用说明.md    首次准备、日常运行、失败和停止方式
├── 启动入口       按电脑系统生成；插件则注明按钮位置
├── 代码/
└── 输出/          有实际结果时才创建
```

同名不覆盖，续作沿用旧目录。你也可以明确指定其他保存位置，助手按指定位置执行。桌面脚本只用系统 Shell / PowerShell，不要求开发运行时；桌面无权限时先申请所需权限，无法访问时说明原因并确认替代位置，不自行回退聊天会话目录。桌面本来由 OneDrive/iCloud 同步时，敏感任务应先确认是否改放本地目录。

## 给助手和维护者：如何连接浏览器

**接口优先，由助手执行。** 数据任务默认监听真实查询、验证 HTTP 请求，再开发可复用的采集代码；浏览器主要负责登录、触发和核对。用户明确只要一次官方导出时，不强迫制作工具。

**共用一份 Skill，按“客户端＋运行形态＋真实工具”分流。** 已登录后台优先复用获准且够用的现有会话；本地预览有内置浏览器才优先使用；Playwright 用于能力缺口或隔离测试。选定后保持同一会话，不因截图或空监听反复换浏览器。客户端配置和开发方法见[维护指南](CONTRIBUTING.md)及以下参考。

| 当前环境 | 处理方式 |
|---|---|
| 已有安全网络监听和 HTTP 工具 | 直接复用，不强制更换浏览器 |
| 当前只暴露截图、点击工具 | 按该通道文档核查批准与过滤能力，不套用其他客户端的Developer mode；确认技术缺口且获准后才准备替代通道，不默认退回下载按钮 |
| Codex / Claude Code / OpenCode 需要 MCP | 按各自配置方式接入，不能互抄配置格式 |
| Pi | 核心没有原生 MCP 或内置浏览器；复用已安装且获信任的扩展/CLI，或使用允许的本地脚本；不假造`pi mcp add`命令 |
| 宿主或公司禁止额外通道/安装 | 遵守限制，解释阻塞及回退方案，不绕过权限 |

详细步骤在 [客户端适配](browser-to-tool/references/clients.md)、[环境准备](browser-to-tool/references/setup.md)、[浏览器说明](browser-to-tool/references/browser.md)和 [HTTP采集路线](browser-to-tool/references/http-collection.md)。

浏览器参考里的 Chrome DevTools MCP 配置**只是页面辅助**，关闭直接返回模型的原始网络详情，单独不能完成接口采集。执行任务的助手应复用合规网络工具或本仓库配套脚本；脚本不适用的机制再按实际网站开发。本仓库不是“任何网站一键采集器”。

## 数据和权限

- 用户自行登录，明确目标网站、账户和范围；不自动接管个人所有标签页。
- 受信任本地客户端可在授权内正常使用认证，但 Cookie、令牌、签名不能进入聊天、源码、日志或分享包。不复制个人 profile，不破解登录或访问控制。
- 先本地过滤网络内容，再输出必要证据。Skill 不是运行时沙箱，提示词不等于工具层安全保证。
- 服务端分页先验证 HTTP 一页和下一页；本地分页、单页或零条按HTTP参考验证终点，再按授权处理全量。失败、限流、登录过期、部分结果必须明确。浏览器 fetch 不能冒充无需浏览器的独立客户端。
- 接口路线不可行时才评估官方导出/DOM并说明原因；明确的一次性官方导出需求不强迫造工具。
- 真正的业务写入、对外发送、安装插件、启用定时、部署发布需要相应授权。

## 配套浏览器已经能做什么

- 启动专用可见 Chromium，跨命令保持会话；原标签关闭不主动销毁上下文，允许明确选择已授权业务标签。正常停止、重开后可复用可持久化登录资料。
- 先监听 Fetch/XHR，再通过必要的界面查询取得候选，用共享 Cookie 的 HTTP 请求验证下一页。
- 默认只返回结构；经授权可查请求业务字段，支持包装值、数组路径、根字段及已存在分页参数的必要联动，不能新增任意请求字段。
- 在同一业务页面生成获准截图，输入/可编辑区域/iframe遮罩，PNG原子保存而不经JSON IPC传输；这不是登录页采集或通用DLP。
- 字段样本在本地过滤后输出到桌面任务，文件不覆盖；样本仍不是通用全量采集器。
- 正常停止、空闲退出、异常启动清理；保留 profile，不强杀其他浏览器或删除登录资料。

助手使用[实际调用说明](browser-to-tool/references/playwright-runtime.md)。设计、已测与未测范围见[实施与验收记录](docs/playwright-browser-design.md)。这仍是调查/小样本通道，不等于已经为你的后台写好完整采集器；样本截断、脱敏、登录过期都不能当完整成功。

## 在另一台 Mac 上测试

先按上面说明安装或更新完整 Skill，已有版本先备份，并新开对话加载。默认先核查已有获准浏览器，不需要为更新Skill重新登录。不要复制这台电脑的 profile、Cookie、`node_modules`或浏览器缓存；只有选择新专用浏览器时才需要本人登录。

下面是**明确测试配套运行器**的可选场景，不是所有任务的默认路线：

把下面这段话发给助手：

> 请使用最新 browser-to-tool 的配套 Playwright 脚本，为 `<后台网址>` 做接口采集验证。先创建桌面任务目录、检查环境，缺依赖时说明用途并等我同意再准备。打开专用浏览器由我登录，不接管个人 Chrome。先监听真实查询，服务端分页验证 HTTP 一页和下一页；本地分页、单页或零条按HTTP参考验证终点。不先点下载，不直接全量保存。过程和结果留在同一任务目录，结束后正常停止浏览器。

## 当前验证状态

共享格式、文档引用及 macOS 桌面脚本已有本地检查；真实 Chromium 合成测试覆盖登录重启、POST分页、大整数、认证过滤、账户变化、重定向、停止与跨命令生命周期，并检查过可见窗口。**四种客户端的完整模型行为、Windows/Linux实机与真实网站采集尚未验收**，不能因为能安装就说已能自动采集。

维护者可运行：

```sh
python3 维护者/check.py
# 完成获准的Node/Playwright/Chromium准备后：
node --test 维护者/browser*.test.mjs
```

Python仅供维护者自检，不是同事安装或建目录的依赖。Python检查只用临时桌面和合成文件，包含策略文本回归；Node检查使用隔离profile和本地合成网站。两者都不代表四种客户端的模型已经正确执行本Skill。`维护者/evals.json`是待实测场景，不是通过报告。

仓库只包含 Skill、说明和检查，不包含账户、真实业务数据、个人会话、浏览器登录资料或原 Agent 应用。
