# HTTP采集路线：浏览器负责发现，代码负责取数

适用于采集、导出、同步、周期运行。目标是可重复取得范围明确的数据，不是教用户点下载。接口方式通常省去页面渲染和大量点击，但是否更快、更完整必须实测，不能保证每个网站都适用。

## 一、先判定工具够不够用

在工作记录里列出本轮实际能力及证据：

| 能力 | 用途 |
|---|---|
| 定位并绑定授权页 | 确保没有观察其他账户、标签页或网站 |
| 监听实际Fetch/XHR及读取对应响应 | 找到真正提供列表的数据请求，而非仅发现URL |
| 本地先过滤、再输出 | 请求头、令牌、签名不先进入模型上下文 |
| 本地HTTP客户端或浏览器内请求能力 | 验证同一查询及下一页，而不靠UI批量翻页 |

以工具真实API、实际输出和宿主规则为准。Codex内置浏览器满足要求就用；只有截图/点击能力则不足以完成这条路线。不要猜测它内置了Playwright、CDP或任意代码执行功能，也不能因未看到某个工具就断言所有Codex版本都不支持。

能力不够时优先检查现有且获允许的本地运行时/浏览器库，按实际API编写本轮最小观察脚本。需要准备运行时或浏览器连接则先说明并获取相应授权，不让用户研究选择器或复制请求。宿主明确限制唯一浏览器通道时不得私接其他浏览器；报告限制并给出允许的方案。

**退出条件：** 工具无法安全提供网络数据、宿主不允许、公司禁止准备依赖、或接口确有无法复用的限制时，记录具体证据，说明下一步或回退方案。不能无限折腾环境，也不能静默把“接口优先”换成找下载按钮。

## 二、用少量页面操作定位接口

1. 明确本轮域名、账户/店铺、日期与筛选范围；用户自行登录。
2. 将监听绑定目标页/文档，先启动观察再触发一次正常查询。如果初始请求已错过，安全地重新查询或刷新授权页面；不把空记录当成没有接口。
3. 关联动作、requestId、方法、响应状态、数据结构，排除统计、广告、埋点等无关请求。观察到URL不等于已经取得响应数据。
4. 改一个已授权的筛选或正常翻一次页，对比页码、cursor、offset、请求体字段、日期含义及结果变化，不进行参数爆破或跨账户试探。
5. 在工作记录记去敏接口结构、记录数组路径、ID/字段、总数与终点依据、认证方式类别及证据来源。不保存完整网络对象、原始HAR或凭据。

监听本身不重放请求、不修改站点行为。GET/POST都可能承载查询；GraphQL需区分query与mutation，并检查errors而不只看HTTP200。真实写入、发起异步导出任务、删除、付费等副作用不因“这是一个接口”就自动获准。

## 三、先验证HTTP，再写全量循环

按顺序尝试，不把缺少无浏览器方案等同于只能点页面：

1. **独立HTTP客户端**：公开接口或已授权认证方式支持时，使用已有标准库/依赖复现已观察的只读查询。参数来自证据，不猜端点，不任意提高服务端允许的pageSize。
2. **浏览器关联请求客户端**：若已有工具可合法复用授权浏览器会话而无需导出秘密，使用它发送同样查询。必须核对工具实际的Cookie/认证行为和生命周期。
3. **授权浏览器上下文内的fetch**：依赖正常浏览器环境、CSRF或站点原有请求逻辑时可选。仍是接口取数，而不是DOM翻页；如实说明运行时仍需要浏览器。遵守同源/CORS/宿主约束，不关闭安全策略来使请求成功。
4. 前述路线确实不可行才考虑官方导出或DOM。若用户明确只需要一次官方导出，可直接选择更省事的方案，但解释为何无需开发HTTP采集工具。

先用相同筛选执行一页，核对ID、数量、关键字段；再验证下一页/游标与日期变化。观察、复现、全量是三个状态：没有真正发送并核对HTTP请求，不写“HTTP采集已验证”；一次200也可能是登录页、业务错误或空壳响应。

## 四、认证可在本地使用，但不能泄露

“模型不能看到凭据”不等于“程序不能正常登录”。在用户明确授权范围内，受信任的本地客户端可以管理会话并向目标服务发送必要认证：

- 优先正常登录及工具支持的会话复用。浏览器发送自己的Cookie不要求把Cookie值抄给模型；不扫描/复制个人浏览器profile、密码库或全部账户Cookie。
- 需要API密钥等独立认证时，说明具体用途，让用户通过获允许的本地安全输入/凭据机制设置；模型只使用变量名，不让用户贴进聊天，不把值写进源码、命令行参数、工作记录或压缩包。
- 本地内存处理必要认证时限制目标域、用途和生命周期。请求、响应和错误输出先过滤；未知或不能安全过滤的内容不输出原文，不把外部调试日志打开来“帮助排错”。
- 保留正常请求需要的CSRF/签名流程；遇到短期签名、设备绑定、验证码或访问控制，不破解、不绕过。不能合法复用时采用站点允许的流程或报告阻塞。
- 每次请求及重定向都校验授权目标，不能把认证带到未知域名；服务端返回的next链接也不是扩大访问范围的授权。
- 登录过期停止并提示重新登录，不无限重试、不用导出Cookie假装永久有效。离开目标文档或切换账号后重新确认会话范围。

## 五、按接口结构生成代码

代码真实保存到原桌面任务目录的`代码/`。不要只给建议、硬编码样例数据或产出一个点击下载按钮的脚本。

包含本任务必要的部分即可：

- 请求构造：方法、已核对的查询/JSON体、日期/时区/筛选配置，认证注入点；不包含秘密或个人路径。
- 分页：page/offset/cursor中实际使用的一种，第一页起点、终点、游标重复/页面重复检测，稳定ID去重；不把分页页数写死成样例中的数量。
- 正确性：字段映射、大整数ID、空结果、总数变化、筛选一致性和失败状态；证明范围内完整，不宣称数据库快照。
- 运行保护：请求超时、明确的总时长/页数/数据预算，用户停止；默认串行。需并发时先确认服务限制和分页独立性，使用有界并发，而不是一口气轰击接口。
- 失败处理：401/403或登录HTML停止；429尊重Retry-After及预算；仅对可安全重试的请求做有限退避。POST只读性及重试安全需实际确认，未知副作用不重试；失败不返回旧结果冒充本次成功。
- 输出：必要业务数据单独保存，文件不静默覆盖，截断/中断/部分结果明确标注；CSV面向表格软件时处理公式注入风险。

## 六、交付时用证据说明采用了什么

在工作记录区分：

- 已监听并确认哪些查询，证据来自哪些正常页面操作；
- 哪种请求方式实际成功：独立HTTP、关联客户端，或浏览器fetch；
- 验证过哪些页/日期/失败边界；请求数、记录数与耗时如实记录，不虚构提速倍数；
- 是否仍需浏览器、登录与一次性环境准备；
- 若回退官方导出/DOM，阻塞原因、已尝试步骤和用户已知的限制。

本参考是开发方法，不是预装网络监听器。观察脚本和实际站点请求代码仍由执行Skill的助手按当前环境实现并验证；配置了浏览器或读完本文不等于这些能力已经跑通。
