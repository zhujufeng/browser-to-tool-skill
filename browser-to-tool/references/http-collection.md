# HTTP采集路线：浏览器负责发现，代码负责取数

适用于采集、导出、同步、周期运行。目标是可重复取得范围明确的数据，不是教用户点下载。接口方式通常省去页面渲染和大量点击，但是否更快、更完整必须实测，不能保证每个网站都适用。

## 一、先判定工具够不够用

在工作记录里列出本轮实际能力及证据：

| 能力 | 用途 |
|---|---|
| 定位并绑定授权页 | 确保没有观察其他账户、标签页或网站 |
| 监听实际Fetch/XHR及读取对应响应 | 找到真正提供列表的数据请求，而非仅发现URL |
| 本地先过滤、再输出 | 请求头、令牌、签名不先进入模型上下文 |
| 本地HTTP客户端或浏览器内请求能力 | 验证同一查询及下一页，而不靠UI批量翻页 |

先按[浏览器路由与切换门槛](browser.md)固定通道，以真实API、实际输出和宿主规则为准。Codex官方扩展与内置浏览器在获准Developer mode下有网络检查能力；当前版本是否开放、是否能先过滤仍需验证。只有截图/点击不足以完成这条路线，但不应仅因缺端口就换浏览器。

确认能力缺口后，优先检查同一会话已有且获允许的本地运行时/浏览器库，按实际API编写本轮最小观察脚本。需要准备运行时或浏览器连接则先说明并获取相应授权，不让用户研究选择器或复制请求。宿主明确限制唯一浏览器通道时不得私接其他浏览器；报告限制并给出允许的方案。

**退出条件：** 工具无法安全提供网络数据、宿主不允许、公司禁止准备依赖、或接口确有无法复用的限制时，记录具体证据，说明下一步或回退方案。不能无限折腾环境，也不能静默把“接口优先”换成找下载按钮。

**已有站点库/官方API的复用分支：** 已有获信任的适配库或文档化API覆盖任务时，可以直接验证并复用，不必重新逆向其内部请求。记录库版本、官方文档、授权范围和实际返回字段；用真实小样本核对ID、必需字段及终点，涉及分页则在预算内证明跨页连续性。库内部托管分页不等于自己监听了接口，不编造页1/页2请求；网络不可达只能交付待验证实现。列表/详情模式要按实际选项分别验证，例如yt-dlp的`extract_flat='in_playlist'`仍不展开列表中的视频，不能把它叫作完整详情模式；以[官方参数说明](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py)及本机版本为准。后续自行构造分页请求时，仍须满足下述真实请求证据要求。

### 提出回退前，先验证它能补什么

区分“当前助手浏览器只能逐页操作”和“获准开发的独立脚本/插件不能批量”。前者不能单独证明后者。检查现有允许的库、运行时或插件机制，先实现并验证小样本；若必须增加安装/访问权限，指出具体能力缺口与准备步骤，不让同事在API、Cookie、MCP之间猜。准备产品代码不是绕过宿主浏览器限制的许可，未经授权不启用替代通道、导出个人会话或批量执行。

官方API也先逐字段核对覆盖、认证身份和配额，再建议用户准备凭据。例：YouTube的[字幕列表](https://developers.google.com/youtube/v3/docs/captions/list)不包含字幕正文，[字幕下载](https://developers.google.com/youtube/v3/docs/captions/download)需要相应授权及视频编辑权限；不能承诺给一个API Key就能补齐任意公开视频的字幕。未取得的字段保留未验证状态，不把另一条路线称为已可行。

### 文本语言与页面不一致时

以同一业务ID对照用户指定页面的标题/简介、列表响应、详情响应和实际导出，定位从哪一步变了。网站本地化标题不一定是作者原文；浏览器翻译也不是网站响应的证据。记录获准页面的显示口径和来源，未要求翻译就不生成替代文本，不按用户说中文或“包含汉字”推断每条标题都必须中文。

- 核对实际库版本、受支持的语言选项、响应字段及正常会话的语言环境；不盲加`hl`、`lang`或`Accept-Language`并宣称修复。比如[yt-dlp的YouTube参数](https://github.com/yt-dlp/yt-dlp/blob/master/README.md#extractor-arguments)支持`lang`偏好译版元数据；[YouTube videos.list](https://developers.google.com/youtube/v3/docs/videos/list)的`hl`影响`snippet.localized`，没有该语言版本仍会回退默认内容。设置参数只是请求意图，须验证返回值与列表、详情两阶段是否实际生效。
- 同名字段按已确认的来源和语言选择，禁止无条件以详情对象覆盖列表对象。已核对的中文页面标题保留为主标题；确需保留其他版本时分列并说明来源，不把未知版本标成原文。接口无法提供约定文本时，按允许的页面路线取得；仍无法取得就标未完成，不用机器翻译掩盖缺失。
- 语言及来源口径属于恢复条件。旧缓存即使标记成功，也需核对是否符合本轮口径；只补取受影响字段，保留可复用的其他数据与旧导出，生成新文件。不能换成中文参数后仍直接输出旧英文缓存。

### 库报错先定位阶段

1. 以一个已授权对象复现，记录库版本、实际选项、失败阶段及脱敏错误类别。不要在诊断时同时吞掉所有警告和提取错误，导致最后只剩“无详情”；日志过滤后保留必要证据，不能整包输出头、令牌或内部URL。
2. 区分元数据提取、字幕正文、评论分页、媒体格式选择、实际下载及文件导出。只要表格时，不应把音视频格式可下载作为所有元数据可用的前提。`Requested format is not available`只证明当前路径的格式选择失败，尚不能确定网站拦截；查本机版本和官方选项，再做一次针对性小样本，不盲换`best/worst`或播放器身份。
3. yt-dlp的`skip_download`只跳过媒体下载；官方另有实验性的`ignore_no_formats_error`用于无可下载格式时提取元数据。仅在任务只需元数据、版本支持时评估，并核验返回字段；它不能证明字幕/评论成功，也不能忽略认证、限流或业务错误。语义见[官方参数说明](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/YoutubeDL.py)。
4. 已确认权限/风控问题立即停止相应访问；普通同类失败按小的有限次数停止该阶段（如连续3个对象），不要遍历整个清单才发现所有对象都失败。保留成功字段，输出缺失范围与原因；新的同类请求必须有新证据、正常恢复条件及剩余预算。

## 二、用少量页面操作定位接口

1. 明确本轮域名、账户/店铺、日期与筛选范围；用户自行登录。
2. 将监听绑定目标页/文档，先启动观察再触发一次正常查询。如果初始请求已错过，安全地重新查询或刷新授权页面；不把空记录当成没有接口。
3. 关联动作、requestId、方法、响应状态、数据结构，排除统计、广告、埋点等无关请求。观察到URL不等于已经取得响应数据。
4. 改一个已授权的筛选或正常翻一次页，对比页码、cursor、offset、请求体字段、日期含义及结果变化，不进行参数爆破或跨账户试探。
5. 在工作记录记去敏接口结构、记录数组路径、ID/字段、总数与终点依据、认证方式类别及证据来源。不保存完整网络对象、原始HAR或凭据。

监听本身不重放请求、不修改站点行为。GET/POST都可能承载查询；GraphQL需区分query与mutation，并检查errors而不只看HTTP200。真实写入、发起异步导出任务、删除、付费等副作用不因“这是一个接口”就自动获准。

## 三、先验证HTTP，再写全量循环

根据已观察的认证要求选择最低依赖方案，不强迫每个站点依次试完三种方式。已证明页面会话/动态认证必需时直接复用它，不为“独立HTTP优先”反复换窗口或导出凭据；缺少无浏览器方案不等于只能点页面：

1. **独立HTTP客户端**：公开接口或已授权认证方式支持时，使用已有标准库/依赖复现已观察的只读查询。参数来自证据，不猜端点，不任意提高服务端允许的pageSize。
2. **浏览器关联请求客户端**：若已有工具可合法复用授权浏览器会话而无需导出秘密，使用它发送同样查询。必须核对工具实际的Cookie/认证行为和生命周期。
3. **授权浏览器上下文内的fetch**：依赖正常浏览器环境、CSRF或站点原有请求逻辑时可选。仍是接口取数，而不是DOM翻页；如实说明运行时仍需要浏览器。遵守同源/CORS/宿主约束，不关闭安全策略来使请求成功。
4. 按列表、详情及子字段判断前述路线；某部分确实不可行或没有适用接口时，只对这部分考虑获准的页面操作/DOM，保留已经可用的接口。允许“列表HTTP＋详情DOM”或反过来；技术回退仍受同一访问授权和宿主策略约束。若用户明确只需要一次官方导出，可直接选择更省事的方案，但解释为何无需开发HTTP采集工具。

先用相同筛选执行一页，核对ID、数量、关键字段；再验证下一页/游标与日期变化。观察、复现、全量是三个状态：没有真正发送并核对HTTP请求，不写“HTTP采集已验证”；一次200也可能是登录页、业务错误或空壳响应。

### 先证明分页模式，再要求两页证据

一次响应可能已经返回全部记录，页面只做本地分页。先比较页面翻页前后的请求与列表ID；无新请求本身不够，还需核对服务端列表数量/总数、页面第二页ID确实来自已取列表及日期筛选，重放该查询验证。单页/零条结果也记录终点依据，不猜不存在的page参数。换日期或规模后不能默认仍只有一页。

服务端分页的证据不能由猜测的测试夹具代替。在编码前留下四项：真实页1/页2动作与候选标识、请求差异、各自HTTP重放结果、正式列表与身份/总数/日期路径。参数值只展示获准的安全业务字段，其余在本地比较。

- 一次翻页可能同时更新内层`pageNo`与外层`page`；也可能包含无关同名字段。以实际差异和重放为准，不评分猜一个，也不遍历改所有同名字段。
- 区分对象、数组、JSON字符串、包装值。`itemId`若是对象，身份可能在`itemId.value`；不能把对象转字符串、整行JSON或名称作为ID。
- 列表路径整轮保持不变。辅助数组可能比末页长；不能每页重新选最大数组。空列表需区分合法零条、业务错误及结构缺失。
- 对照显示旧改法重复首页时，再写能复现它的合成反例；不要反过来让模拟服务仅识别自己猜的参数。
- 原始协议里的HTTP2伪头不是Fetch/HTTP客户端可直接使用的普通请求头；按协议过滤非法头名和受客户端管理的头，不打印原始头排错，不盲删正常认证流程。
- 未通过上述门槛，只能写“待验证”，不得保存为可复用模板、开放无人值守或让用户反复试安装包。

## 四、认证可在本地使用，但不能泄露

“模型不能看到凭据”不等于“程序不能正常登录”。在用户明确授权范围内，受信任的本地客户端可以管理会话并向目标服务发送必要认证：

- 优先正常登录及工具支持的会话复用。浏览器发送自己的Cookie不要求把Cookie值抄给模型；不扫描/复制个人浏览器profile、密码库或全部账户Cookie。
- 需要API密钥等独立认证时，说明具体用途，让用户通过获允许的本地安全输入/凭据机制设置；模型只使用变量名，不让用户贴进聊天，不把值写进源码、命令行参数、工作记录或压缩包。
- 本地内存处理必要认证时限制目标域、用途和生命周期。请求、响应和错误输出先过滤；未知或不能安全过滤的内容不输出原文，不把外部调试日志打开来“帮助排错”。
- 保留正常请求需要的CSRF/签名流程；遇到短期签名、设备绑定、验证码或访问控制，不破解、不绕过。不能合法复用时采用站点允许的流程或报告阻塞。
- 每次请求及重定向都校验授权目标，不能把认证带到未知域名；服务端返回的next链接也不是扩大访问范围的授权。
- 登录过期停止并提示重新登录，不无限重试、不用导出Cookie假装永久有效。离开目标文档或切换账号后重新确认会话范围。

## 五、按接口结构生成代码

代码真实保存到原桌面任务目录的`代码/`。不要只给建议、硬编码样例数据或产出一个点击下载按钮的脚本。

包含本任务必要的部分即可：

- 请求构造：方法、已核对的查询/JSON体、日期/时区/筛选配置，认证注入点；不包含秘密或个人路径。服务端已有相对日期枚举时保留其已验证语义，不把“近1日”擅改为客户端计算的昨天，也不长期重放初始化当天的绝对日期。
- 分页：已验证的page/offset/cursor机制及必要联动字段，第一页起点、终点、游标重复/页面重复检测，稳定标量ID去重；不把分页页数写死成样例中的数量。
- 正确性：字段映射、大整数ID、空结果、总数变化、筛选一致性和失败状态；证明范围内完整，不宣称数据库快照。
- 运行保护：请求超时、明确的总时长/页数/数据预算，用户停止；默认串行。需并发时先确认服务限制和分页独立性，使用有界并发，而不是一口气轰击接口。
- 失败处理：401/403或登录HTML停止；429尊重Retry-After及预算；仅对可安全重试的请求做有限退避。POST只读性及重试安全需实际确认，未知副作用不重试；失败不返回旧结果冒充本次成功。详情任务分阶段保存最小必要业务结果及状态，写入成功后再标记完成；按对象ID及字段/子列表状态恢复，不因存在对象记录就跳过失败或待补字段，不重复已成功部分。恢复前核对原范围与来源条件，接口改变时重新验证；权限拒绝不能因“继续”就自动重试。
- 输出：必要业务数据单独保存，文件不静默覆盖，截断/中断/部分结果明确标注；CSV面向表格软件时处理公式注入风险。全量前先核对业务样例与固定列，金额/比例单位由官方字段或页面证据决定；技术包装字段不默认展开成业务列。主列表缺失和官方允许的补充指标缺值分开校验，有证据的合法缺值留空并说明，不能全部填零或盲目失败。

## 六、交付时用证据说明采用了什么

在工作记录区分：

- 已监听并确认哪些查询，证据来自哪些正常页面操作；
- 哪种请求方式实际成功：独立HTTP、关联客户端，或浏览器fetch；
- 验证过哪些页/日期/失败边界；请求数、记录数与耗时如实记录，不虚构提速倍数；
- 是否仍需浏览器、登录与一次性环境准备；
- 若回退官方导出/DOM，阻塞原因、已尝试步骤和用户已知的限制。

本参考是开发方法，不是预装网络监听器。观察脚本和实际站点请求代码仍由执行Skill的助手按当前环境实现并验证；配置了浏览器或读完本文不等于这些能力已经跑通。
