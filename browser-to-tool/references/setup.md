# 环境准备：同事不需要先学开发

默认本机已有Codex、Claude Code、Pi或OpenCode等编码助手。不要再安装客户端；也不要因为客户端能运行就断言终端有Node、npm、Python、Git、Chrome或编译工具。

## 先检测，不先安装一整套

1. 按[客户端识别表](clients.md)确认客户端、桌面/终端/IDE或远程形态、真实工具与执行位置，再确认操作系统、当前目录和允许写入的位置；不输出整个环境变量列表或用户配置内容。
2. 先用`workspace.sh`（Mac/Linux）或`workspace.ps1`（Windows）建桌面任务目录。脚本只依赖系统命令；不要为了建文件夹安装Node/Python/Git。系统策略拒绝执行时，不绕过策略；说明错误并使用获允许的文件操作方式或寻求管理员协助。
3. 只检查本任务需要的工具：
   - Mac/Linux用`command -v`检查命令是否存在，存在后再取`--version`。
   - Windows用`Get-Command <命令> -ErrorAction SilentlyContinue`；Python存在别名不代表解释器已安装，要实际验证版本，不能触发商店弹窗就说通过。
   - 浏览器按任务检查能力：采集需要监听Fetch/XHR、过滤后的响应证据及HTTP执行，不是只看能否打开授权页面。按[浏览器用途与切换门槛](browser.md)优先复用现有登录会话；按当前通道文档核查权限和过滤能力；仅实际提供Codex浏览器工具时检查其Developer mode，不以缺9222端口判定不能监听。确认缺口才准备允许的新通道，不因省安装而默认改做DOM采集。也不要把一个仅提供页面控制的MCP配置说成已能监听接口。
4. 在工作记录写简表：工具 / 已有版本或缺失 / 本任务是否需要 / 下一步。不要把“不存在”写成故障，也不反复运行注定失败的命令。

## 缺依赖时按这个顺序处理

1. **能不装就不装。** 已有平台原生能力、纯HTML小工具、适合任务的无构建浏览器插件、系统自带脚本，都可以是方案；但不能牺牲正确性或变成用户手动找接口。静态HTML不能凭空跨域读后台，插件安装和权限仍需授权。
2. **确实需要才准备。** 用一句话解释：“浏览器连接工具需要Node，它负责运行连接器；只需准备一次。”说明是否联网下载、安装位置、是否修改系统或需要管理员权限，获得授权再做。
3. **由助手完成能完成的部分。** 核对官方安装来源与当前支持版本，优先已有安装器/包管理器或官方用户级安装方式；不要连包管理器也无理由全装。下载前确认来源，能够核对签名/校验值就核对；不得执行来历不明的`curl | sh`、安装破解程序或关闭系统安全检查。
4. **用户只处理真正需要本人的步骤。** 管理员密码、浏览器登录、公司批准、系统安装确认由用户完成，不索要或记录密码。说清点击哪里，完成后重新检测。
5. **安装成功不等于能用。** 重新检查可执行文件路径、版本、最小命令、浏览器连接和任务目录读写；PATH刚更新时可能需重启客户端。失败记下准确原因，不盲目重装。

常见对应关系：

| 情况 | 处理 |
|---|---|
| 没有Node/Python/Git | 仍可读取Skill、建目录、记录需求和选择方案；按实际需要准备，不全装 |
| 需要配套Playwright浏览器 | 先读[实际运行说明](playwright-runtime.md)，检测Node 22+及npm；获准后按锁文件安装Playwright与专用Chromium。不复制个人Chrome；Windows运行器暂禁用，不能取消检查绕过 |
| 没有Node，但需要Chrome DevTools MCP | 征得同意后准备官方支持的Node LTS及其npm/npx，再配置MCP |
| 没有Python，但选择Python交付 | 先考虑已有运行时或更简单形式；仍最适合Python时协助准备解释器及任务目录内虚拟环境 |
| 没有Git | 普通工具开发不要求Git；没有版本控制也不阻止保存代码，不强制初始化仓库 |
| 没有Chrome | 先检查已授权的其他浏览器工具；若确需Chrome DevTools MCP，说明它支持Chrome，获准后准备，不把Edge/Safari当作已验证兼容 |
| 当前浏览器只暴露点击/截图 | 先读当前通道文档，核实其权限/站点批准及先行过滤，不套用其他客户端的Developer mode设置；组织拒绝不能绕过，确认技术缺口且获准才准备其他通道，不能直接找下载按钮 |
| 公司禁止安装/网络下载 | 不绕过。采用已有能力或生成可供有环境机器运行的代码，并明确本机尚未验证；接口路线受阻时说明原因与回退，不隐瞒降级 |
| WSL、远程容器或云端会话 | 不能假定能访问真实桌面/Chrome；确认本地目录映射和浏览器连接方式，否则请用户切回本机环境 |

## 把首次准备和日常使用分开

交付的`使用说明.md`先写“第一次使用需要做什么”，再写“以后每次如何使用”。第二次不重装依赖、不新建重复任务文件夹，不把依赖安装错误交给用户自行搜索。

依赖/虚拟环境按选用工具的惯例保存在任务代码目录或系统缓存；浏览器profile和凭据留在工具私有目录，不打包分享。分享前只选择代码和必要文档，不发送环境目录、真实业务数据或登录状态。
